The map

Three tools, three jobs.

MATLAB

Scripts and math. Holds the numbers (cells, motor, rules), runs the sizing, and plots results.

Simulink

Blocks and wires that run over time. Turns “how much torque, how fast” into current, voltage and state of charge.

Stateflow

States and arrows inside Simulink. Decides when: is high voltage on? Are we in EV or hybrid? Did something fault?

The workflow we use.Parameters live in a MATLAB script → the Simulink model reads them → Stateflow charts sit inside the model → results come back to MATLAB for plots. One script can build, run and plot everything.
Part 1 · MATLAB

Put the cell in a struct.

A struct keeps related numbers together, so every script uses the same values.

% practice_params.m  - made-up practice numbers, not a real cell
cellSpec.Vnom  = 3.6;     % V, nominal
cellSpec.Vmax  = 4.2;     % V, full
cellSpec.Vmin  = 2.8;     % V, empty

cellSpec.Rohm  = 0.008;   % ohm
cellSpec.kg    = 0.070;   % kg

rules.Emax_Wh  = 5000;    % Wh, competition rule

Part 1 · MATLAB

Size the pack in six lines.

This is Lecture 1’s math, typed once. Change the cell and run it again.

% pack_sizing.m  - run practice_params.m first
Smin = ceil(motor.Vmin / cellSpec.Vmin);       % 90
Smax = floor(rules.packVmax / cellSpec.Vmax);  % 95
S    = Smax;                                   % most voltage
P    = floor(rules.Emax_Wh / (S * cellSpec.Wh));  % 3
E_kWh = S * P * cellSpec.Wh / 1000;            % 4.104

fprintf('%ds%dp: %.2f kWh, %.0f V nominal\n', ...
        S, P, E_kWh, S*cellSpec.Vnom)
Command Window
>> pack_sizing
95s3p: 4.10 kWh, 342 V nominal

What each function does

ceil rounds up (you can’t have 89.3 cells). floor rounds down (a 96th cell would pass 400 V). fprintf prints with a format: %d whole number, %.2f two decimals.

Part 1 · MATLAB

Turn it into a function you can reuse.

Save this as its own file named packCalc.m. Now anyone can size any pack in one line.

function pk = packCalc(cellSpec, S, P)
%PACKCALC  Pack numbers from one cell and an S x P layout.
pk.Vnom  = S * cellSpec.Vnom;
pk.Vmax  = S * cellSpec.Vmax;
pk.Vmin  = S * cellSpec.Vmin;
pk.Ah    = P * cellSpec.Ah;
pk.E_kWh = S * P * cellSpec.Wh / 1000;
pk.kg    = S * P * cellSpec.kg;
pk.Icont = P * cellSpec.Ah * cellSpec.Ccont;
pk.R     = S * cellSpec.Rohm / P;
end

Part 1 · MATLAB

Plot the motor’s torque and power.

min picks whichever limit is lower at each speed: the torque limit, or the power limit. That one line makes the “flat torque, then flat power” shape.

Tpk_axle = 1500;  Ppk = 150e3;    % practice motor
n  = linspace(0, 15000, 300);       % motor rpm
w  = n * 2*pi/60;                    % rad/s
Tm = min(Tpk_axle/motor.G, Ppk ./ max(w, 1));
Pm = Tm .* w;                         % watts

figure
yyaxis left;  plot(n, Tm, 'LineWidth', 2)
ylabel('Motor torque (N·m)')
yyaxis right; plot(n, Pm/1e3, 'LineWidth', 2)
ylabel('Power (kW)')

Part 2 · Simulink

Blocks, wires, and time.

A Simulink model is a diagram that runs. Each block does one thing; each wire carries a signal that changes over time.

Sources

Where signals start: Constant, Step, From Workspace (a drive cycle from MATLAB).

Math

Gain (× a number), Product (× or ÷ two signals), Sum (+ or −), Integrator (adds up over time).

Sinks

Where signals end: Scope to look, To Workspace to send results back to MATLAB.

  1. Type simulink, choose Blank Model.
  2. Open the Library Browser, drag in Constant, Gain, Scope.
  3. Drag from the arrow on one block to the next to wire them.
  4. Double-click the Gain, set it to 3. Press Run, double-click the Scope.
Part 2 · Simulink

The battery-to-axle chain as blocks.

Read it left to right: the drive cycle asks for axle speed and torque, and the model works back to how much current the pack must give.

Motor + gearbox

ωmotor = rpmaxle × G × 2π/60. Tmotor = Taxle / G. Power = T × ω.

Inverter

PDC = Pshaft / η. One Gain block.

Battery

I = PDC / V. V = Voc − I·R. SOC drops by ∫I dt / (Ah × 3600).

Why the Memory block?Current depends on voltage, and voltage depends on current. Wiring that straight back makes an algebraic loop. The Memory block hands back last step’s voltage, which breaks the loop.
Part 2 · Simulink

Or build the whole model from a script.

This is how our team’s build_*.m files work: a script makes the blocks and wires, so the model can be rebuilt any time and reviewed in Git.

% build_rear_chain.m  - run practice_params.m first. Written without MATLAB: check it runs.
mdl = 'rear_chain';
if bdIsLoaded(mdl), close_system(mdl, 0); end
new_system(mdl); open_system(mdl);
pk = packCalc(cellSpec, 95, 3);
Voc = pk.Vnom; Rpack = pk.R; AhPack = pk.Ah; G = motor.G; eta = motor.eta;

% practice drive request: axle speed ramps to 1000 rpm, torque 1000 then 300 N·m
t = (0:0.01:30)';
axleRpm = [t, min(1000, 100*t)];
axleTq  = [t, 1000*(t < 8) + 300*(t >= 8)];

b = @(lib, name) add_block(lib, [mdl '/' name]);
b('simulink/Sources/From Workspace', 'AxleRpm');  set_param([mdl '/AxleRpm'], 'VariableName', 'axleRpm');
b('simulink/Sources/From Workspace', 'AxleTq');   set_param([mdl '/AxleTq'],  'VariableName', 'axleTq');
b('simulink/Math Operations/Gain', 'ToOmega');      set_param([mdl '/ToOmega'], 'Gain', 'G*2*pi/60');
b('simulink/Math Operations/Gain', 'ToMotorTq');    set_param([mdl '/ToMotorTq'], 'Gain', '1/G');
b('simulink/Math Operations/Product', 'Pshaft');
b('simulink/Math Operations/Gain', 'Inverter');     set_param([mdl '/Inverter'], 'Gain', '1/eta');
b('simulink/Math Operations/Product', 'Current');   set_param([mdl '/Current'], 'Inputs', '*/');
b('simulink/Math Operations/Gain', 'IR');           set_param([mdl '/IR'], 'Gain', 'Rpack');
b('simulink/Sources/Constant', 'Voc');              set_param([mdl '/Voc'], 'Value', 'Voc');
b('simulink/Math Operations/Sum', 'Vterm');         set_param([mdl '/Vterm'], 'Inputs', '+-');
b('simulink/Discrete/Memory', 'LastV');             set_param([mdl '/LastV'], 'InitialCondition', 'Voc');
b('simulink/Math Operations/Gain', 'ToSOC');        set_param([mdl '/ToSOC'], 'Gain', '-1/(3600*AhPack)');
b('simulink/Continuous/Integrator', 'SOC');         set_param([mdl '/SOC'], 'InitialCondition', '0.9');
for s = {'soc', 'I', 'V'}
    b('simulink/Sinks/To Workspace', ['out_' s{1}]);
    set_param([mdl '/out_' s{1}], 'VariableName', s{1}, 'SaveFormat', 'Timeseries');
end

w = @(a, z) add_line(mdl, a, z, 'autorouting', 'on');
w('AxleRpm/1', 'ToOmega/1');   w('AxleTq/1', 'ToMotorTq/1');
w('ToOmega/1', 'Pshaft/1');    w('ToMotorTq/1', 'Pshaft/2');
w('Pshaft/1', 'Inverter/1');   w('Inverter/1', 'Current/1');
w('LastV/1', 'Current/2');     w('Current/1', 'IR/1');
w('Voc/1', 'Vterm/1');         w('IR/1', 'Vterm/2');
w('Vterm/1', 'LastV/1');       w('Current/1', 'ToSOC/1');
w('ToSOC/1', 'SOC/1');         w('SOC/1', 'out_soc/1');
w('Current/1', 'out_I/1');     w('Vterm/1', 'out_V/1');

set_param(mdl, 'StopTime', '30', 'Solver', 'ode4', 'FixedStep', '0.01');
Simulink.BlockDiagram.arrangeSystem(mdl);
out = sim(mdl);

Fixed-step ode4 at 0.01 s keeps the Memory block’s one-step delay small. Save the model with save_system(mdl) once it runs.

Part 3 · Stateflow

States, arrows, and conditions.

Simulink is good at “how much”. Stateflow is good at “which one”: a system that is always in exactly one state, and moves when a condition becomes true.

State

A rounded box. Its entry: actions run once when you arrive; during: runs every step you stay.

Transition

An arrow with a condition in square brackets. Checked every step; taken the moment it’s true.

Default arrow

The arrow with a dot on its tail. It picks the state the chart starts in.

  1. In Simulink, add a Chart from the Stateflow library and double-click it.
  2. Draw a state, type its name and entry: line.
  3. Drag from one state’s edge to another to make an arrow; click it and type the condition.
  4. Open the Symbols pane to make each name an input, output or local, then wire the chart’s ports.

Part 3 · Stateflow

How to type the precharge chart.

Copy these into the states and arrows exactly. Names in the Symbols pane: inputs hvRequest, vBus, vPack, isoFault, reset; outputs neg, pre, pos.

Open
  entry: neg = false; pre = false; pos = false;

Precharge
  entry: neg = true; pre = true; pos = false;

Closed
  entry: pos = true; pre = false;

Fault
  entry: neg = false; pre = false; pos = false;
% default arrow points at Open
Open      -> Precharge  [hvRequest && ~isoFault]
Precharge -> Closed     [vBus >= 0.95*vPack]
Precharge -> Fault      after(3, sec)
Closed    -> Open       [~hvRequest]
Open, Precharge, Closed
          -> Fault      [isoFault]
Fault     -> Open       [reset && ~isoFault && ~hvRequest]
Order matters.If two arrows leave one state and both are true, Stateflow takes the one with the lower number (shown on the arrow). Put the fault arrow first so safety always wins.

Part 4 · Put it together

Stateflow decides. Simulink does.

The precharge chart’s pos output gates power in the chain: no closed contactor, no current. One Switch block connects the two.

EE1 · Instrumentation

Runs this logic on the TI board. Real vBus and isoFault come in over sensors and CAN.

EE2 · Controls

Owns the chain model and the mode supervisor. Feeds it real duty-cycle data.

HVB

Owns packCalc and the pack numbers the whole model reads.
